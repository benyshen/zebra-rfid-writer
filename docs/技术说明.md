## 2. 连接层：两种 LLRP 角色

Zebra 固定式读写器的 LLRP 有两种工作模式，**决定连接代码方向**：

| 模式 | 谁监听 | SDK 用法 |
|---|---|---|
| Server | 读写器监听 5084 | `new RFIDReader(ip, port, timeout)` + `reader.Connect()` |
| Client | 读写器主动外连（约每 2 秒重试） | 本机 `TcpListener` → `AcceptSocket()` → `new RFIDReader(peerIp, port, ms)` → `reader.AcceptConnection(sock)` |

关键点：

1. **`AcceptConnection(Socket)` 是官方支持的入口**，不需要写 TCP 中继/代理。
2. Client 模式下，读写器连上后会先发一条 32 字节的 `READER_EVENT_NOTIFICATION`；主机不回话它会在几秒后断开重连。
3. 判据：在候选端口 `TcpListener` 监听 30~60 秒，收到来自读写器 IP 的连接 = Client 模式。Client 模式下读写器**不监听任何端口**，扫端口永远找不到它。
4. 用户口中的"读写器 IP"有时其实是**本机 IP**（Client 模式里配置的就是"连到哪台主机"）——先 `Get-NetIPAddress` 核对归属。

### 2.1 自动重连（必须做，否则会出现莫名其妙的"未连接"）

初版只 `accept` 一次，会话一掉就永久失联，表现为"能盘点、一停止盘点再写就提示请先连接读写器，必须断开重连"。修正后的结构：

```csharp
while (!_disconnecting) {
    sock = listener.AcceptSocket();          // 掉线后回到这里，接住读写器的重连
    if (!ipFilter(peer)) { sock.Close(); continue; }
    reader = new RFIDReader(peer, port, 5000);
    reader.AcceptConnection(sock);
    AttachEvents(reader);
    _connected = true;  Raise(true, peer);
    MonitorSession(reader);                   // 阻塞直到会话结束
    _connected = false; reader.Dispose();     // 清理后继续循环
}
```

- **不要**用 SDK 的 `RFIDReader.IsConnected` 做业务判断：某些状态下它返回 false 甚至抛异常，与真实会话不一致。自己维护 `_connected` 标志。
- `MonitorSession` 轮询 `IsConnected` 时要求**连续 3 次（约 1.2 秒）false** 才判定掉线，避免 SDK 瞬时误报导致无谓重建。
- 批量写入循环里每张标签前检查连接，断开则最多等 20 秒重连后继续，避免"掉一次线整批全失败"。

## 3. 盘点

```csharp
reader.Events.ReadNotify += OnReadNotify;      // e.ReadEventData.TagData
reader.Events.NotifyReaderDisconnectEvent = true;
reader.Actions.Inventory.Perform();            // 开始
reader.Actions.Inventory.Stop();               // 停止
```

`TagData`：`TagID`（大写十六进制串）、`PC`、`AntennaID`、`PeakRSSI`、`TagSeenCount`。

UI 侧：事件在 SDK 线程触发 → `BeginInvoke` 收集到 `_pending` → 250ms 定时器合并刷新 `DataGridView`（逐事件刷会卡）。按 EPC 去重并保留首次发现顺序，`TagSeenCount` 只用于显示次数、不参与排序。

## 4. 写入

| 目标 | API | 单位 |
|---|---|---|
| EPC 整条 | `Actions.TagAccess.WriteTagIDWait(tagID, WriteSpecificFieldAccessParams{WriteData, WriteDataLength, AccessPassword}, null)` | 字节；SDK 自己处理 PC 长度位 |
| USER 区 | `Actions.TagAccess.WriteWait(tagID, WriteAccessParams{MemoryBank=USER, ByteOffset, WriteData, WriteDataLength, AccessPassword}, null)` | **字节**（`ByteOffset` = 起始字 × 2） |
| 回读 | `Actions.TagAccess.ReadWait(tagID, ReadAccessParams{MemoryBank, ByteOffset, ByteCount}, null)` → `TagData.MemoryBankData` | 字节 |

关键细节：

1. 目标标签靠 `tagID`（当前 EPC 字串）定位，一次一张；序列化 = for 循环逐张写，天然满足"按读取列表一一写入"。
2. **写完必须回读校验**；EPC 写入后用**新 EPC** 当 tagID 去 `ReadWait`（写成功后标签身份已变），USER 用原 tagID。
3. 失败重试 2~3 次，间隔 100~200ms。
4. **EPC 长度不要随手改**：把 96 位标签写成更短会成功，再写回长 EPC 可能失败并留下*部分写入*的脏 EPC（标签以新 EPC 出现，按原 EPC 定位全部 `TAG_NOT_FOUND`）。程序默认把数据补齐到该标签原有 EPC 长度；"允许改变 EPC 长度"是显式风险开关。恢复办法：重新盘点拿到标签当前真实 EPC → 以它为 tagID 用 `WriteTagIDWait` 写回原始整段（同长度即可成功）。

## 5. 序列化规则

见 `SerialFormat.cs`：

```
第 i 张的序列号序号 = repeat<=1 ? i : i/repeat      // repeat = 写入重复次数
数值 = 起始值 + 步进 × 序号
文本 = 数值按 16/10 进制格式化，左补 0 到"位数"
HEX 原样：prefix + 文本 + suffix
ASCII 编码：prefix(HEX) + 文本每字符转 2 位 HEX + suffix(HEX)
EPC 区：不足标签原有长度时左补 00；超过则报错（除非勾选允许改变长度）
```

自检：`RfidWriter.exe --repeatplan 7 3` 打印"第几张 → 序列号 → 数据"，并验证"同组必同值、跨组必换值"。

## 6. 天线功率

- 功率不是 dBm 直填，是**档位索引**：`reader.Config.Antennas[a].GetRfConfig().TransmitPowerIndex = idx; SetRfConfig(cfg)`。
- `ReaderCapabilities.TransmitPowerLevelValues` 给的是原始整数，**FXR90 实测为 dBm×100**（1000…2920 → 10.0…29.2 dBm，共 193 档）。量级判断：max>1000 除 100，max>100 除 10。
- 设置后回读 `GetRfConfig().TransmitPowerIndex` 确认。
- 现场效果（天线 1 近场同批标签）：29.2 dBm 读 56 个 → 15 dBm 读 10 个，串读明显收敛。

## 7. 高 DPI 布局

- 不做 DPI 感知的 .NET Framework 程序在 125% 缩放下被 Windows 位图放大：`GetWindowRect` 返回虚拟化坐标，截图只截到一块，看起来"界面被裁了"。
- `AutoScaleMode.Dpi` + 手工 `AutoScaleDimensions=(96,96)` **会反向缩到 0.8**（本机实测窗口从 1180 变 958），不要用。
- 本项目做法：`app.manifest` 里 `dpiAware=true` + `AutoScaleMode.None` + 启动时按 `CreateGraphics().DpiX / 96` 递归等比缩放所有控件（含 `DataGridView` 列宽、行高、`ClientSize`、`MinimumSize`）。
- 设计基准 1180×764 逻辑像素，125% 下实际 1475×955，适配 1920×1200 屏。

## 8. 其它 SDK 坑

1. `reader.Events` 必须在 `new RFIDReader(host, port, timeout)`（或设好 `HostName`/`Port`）之后才能访问，否则抛 `InvalidUsageException`；未捕获时表现为 `由于 Exception.ToString() 失败，因此无法打印异常字符串` 这种看不懂的崩溃。
2. 异常类型：`OperationFailureException`（有 `Result` / `StatusDescription` / `VendorMessage`）、`InvalidUsageException`（有 `Info`），其余为普通 `Exception`。
3. EPC 写入最稳的是 `WriteTagIDWait`（SDK 处理 PC 位），不要自己算 PC 字。
4. `ReaderCapabilities` 里固件字段被拼成 `FirwareVersion`（少了个 m），照抄即可。

## 9. 命令行自测

每个分支都是可复现的真机验证，改动后建议全跑一遍：

| 命令 | 验证内容 |
|---|---|
| `--inv 5084 6` | 连接 + 盘点，打印标签总数 |
| `--diag 5084` | 盘点→停止→设功率→写回原值→再盘点（回归"停止后不能再写"的 bug） |
| `--killtest 5084` | 强制掉线 → 自动重连 → 重连后设功率+写入 |
| `--filtertest 5084 <IP>` | 监听 IP 过滤：错 IP 拒连、对 IP 能连 |
| `--repeatplan N R` | 重复次数映射（不动标签） |
| `--powerinfo 5084` | 功率档位表 + 各天线当前功率 + 不同功率下盘点数量对比 |
| `--restore 5084 <当前EPC> <原始EPC>` | 定点还原某标签 EPC（含 PC 分步写兜底） |
| `--selftest 5084 2` | 写序列号并还原（**会真的改标签**） |
